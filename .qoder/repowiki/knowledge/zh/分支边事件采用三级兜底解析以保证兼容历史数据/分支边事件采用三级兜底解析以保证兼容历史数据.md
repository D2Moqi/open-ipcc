# 分支边事件采用三级兜底解析以保证兼容历史数据

_来源：cf8c29b → 81b13a1 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
DB 中 cc_flow_info id=7 的两种判断器边形态不一致：判断器1 分支边有 startPoint.name（IF/ELSE_IF_1/ELSE）但无 event；判断器2 分支边既无 event 也无 startPoint.name，只有 sourceAnchorId。buildStateMachine 若直接用 edge.getEvent() 会导致建机异常。

## 决策驱动
- 向后兼容历史保存的数据
- 与 FlowConditionHandler 共用同一计算逻辑保证建边与触发同源
- 解析失败必须显式报错而非静默跳过

## 备选方案
- **仅按 startPoint.name 解析** _（已否决）_ — 优点：实现简单；缺点：DB 实测判断器2 分支边无 name，会漏边导致流程第二段走不通
- **仅按 sourceAnchorId 推算** _（已否决）_ — 优点：覆盖旧数据；缺点：丢失前端已写入的 event 语义
- **event → startPoint.name → sourceAnchorId 三级兜底** — 优点：优先保留新数据语义，同时兼容旧数据

## 决策
在 FlowEventListener.resolveEdgeEvent 中实现三级解析：优先用 edge.event；其次从 startPoint.name 推导 next_IF/next_ELSE_IF_n/next_ELSE；最后回退 sourceAnchorId 取 branchIndex 并查源判断器 branches[branchIndex].branchType 推算；解析失败记 ERROR 日志并跳过该边。

## 影响
建边与条件执行路径完全一致，新增分支类型时需同时更新 buildStateMachine 与 FlowConditionHandler 中的推导逻辑。
