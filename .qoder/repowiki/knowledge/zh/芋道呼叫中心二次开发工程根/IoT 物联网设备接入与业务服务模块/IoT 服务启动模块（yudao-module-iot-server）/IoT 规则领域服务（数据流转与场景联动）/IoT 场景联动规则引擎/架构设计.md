模块以 `IotSceneRuleService`/`IotSceneRuleServiceImpl` 为业务入口，对外暴露 CRUD、分页查询、按状态查询以及 `executeSceneRuleByDevice`/`executeSceneRuleByTimer` 两类执行入口；管理后台通过 `IotSceneRuleController`（`/iot/scene-rule`）暴露 REST API，使用 `@PreAuthorize` 进行权限控制。

内部采用策略+工厂模式组织扩展点：
- `matcher/` 子包定义 `IotSceneRuleMatcher` 基础接口及 `IotSceneRuleTriggerMatcher`（触发器）、`IotSceneRuleConditionMatcher`（条件）两个子接口，具体实现按类型拆分到 `trigger/` 和 `condition/` 子目录；`IotSceneRuleMatcherManager` 在构造时注入所有 `IotSceneRuleMatcher` Bean，按优先级排序后分别构建触发器和条件的映射表，提供 `isMatched`/`isConditionMatched` 统一匹配入口。
- `action/` 子包定义 `IotSceneRuleAction` 执行器接口，现有实现覆盖告警恢复/触发、设备属性设置、服务调用等动作类型，由上层根据规则中的 Action 配置分派执行。
- `timer/` 子包通过 `IotSceneRuleTimerHandler` 将规则中的 CRON 表达式注册到 `IotSchedulerManager`（Quartz），任务名为 `iot_scene_rule_timer_{id}`，并在更新/禁用规则时自动注销或暂停对应任务；`IotTimerConditionEvaluator` 用于时间类条件求值。

依赖方向单向向下：Controller → Service → MatcherManager/Action/TimerHandler → 底层枚举与 DO，新增触发器、条件或动作只需实现对应接口并被 Spring 容器发现即可被管理器自动装配。
