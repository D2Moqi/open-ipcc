- 每个下游 sink 类型实现一个独立的 `IotDataRuleAction` 组件，并通过 `getType()` 返回对应的 `IotDataSinkTypeEnum` 值以进行类型分发。
- 需要复用连接/会话的 sink（数据库、MQ、TCP、WebSocket 等）继承 `IotDataRuleCacheableAction`，由基类通过 Guava Cache 管理生产者实例的创建、获取、失效与关闭。
- Controller 方法统一使用 `@Valid` 校验请求体、`@Operation` 描述接口、`@PreAuthorize("@ss.hasPermission('iot:...')")` 声明权限，并以 `CommonResult.success(...)` 返回结果。
- Service 接口与实现分离，CRUD 方法入参使用 VO（SaveReqVO/PageReqVO），返回值使用 DO 或 PageResult，Controller 中再通过 `BeanUtils.toBean` 转换为 RespVO。
- Action 的 `execute` 方法内部对异常进行 try-catch 并记录结构化日志（包含 message id、config、url 等上下文），避免单条规则失败影响整体流转。
