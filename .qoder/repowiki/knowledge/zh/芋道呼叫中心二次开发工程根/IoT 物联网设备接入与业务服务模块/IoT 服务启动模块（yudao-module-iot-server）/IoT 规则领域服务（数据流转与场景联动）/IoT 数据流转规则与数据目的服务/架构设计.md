模块采用典型的 Controller-Service-Action 三层结构：
- Controller 层：`IotDataRuleController` 与 `IotDataSinkController` 暴露 `/iot/data-rule` 与 `/iot/data-sink` REST 接口，统一使用 `CommonResult` 包装并基于 `@PreAuthorize` 做权限控制。
- Service 层：`IotDataRuleService`/`IotDataSinkService` 及其 Impl 实现规则与 sink 的持久化、分页查询、缓存读取及核心入口 `executeDataRule(IotDeviceMessage)`；service 依赖 DO、VO 及枚举类型。
- Action 策略层：`action/IotDataRuleAction` 定义统一的执行契约（`getType()` + `execute(message, dataSink)`），每种下游目标对应一个 `@Component` 实现（如 `IotDatabaseDataRuleAction`、`IotHttpDataSinkAction`、`IotMqttDataRuleAction`、`IotKafkaDataRuleAction`、`IotRabbitMQDataRuleAction`、`IotRocketMQDataRuleAction`、`IotRedisRuleAction`、`IotTcpDataRuleAction`、`IotWebSocketDataRuleAction`），并通过 `tcp/`、`websocket/` 子包封装长连接客户端（`IotTcpClient`、`IotWebSocketClient`）。
- 抽象基类：`IotDataRuleCacheableAction` 基于 Guava `LoadingCache` 缓存各 sink 的生产者实例（默认 30 分钟未访问过期），子类只需实现 `initProducer`/`closeProducer`/`execute(Config)`，由基类负责生命周期与异常日志。
- 依赖方向：Controller → Service → Action（策略），Action 仅依赖 `IotDeviceMessage`、`IotDataSinkDO` 及各自下游客户端，不反向依赖上层。
