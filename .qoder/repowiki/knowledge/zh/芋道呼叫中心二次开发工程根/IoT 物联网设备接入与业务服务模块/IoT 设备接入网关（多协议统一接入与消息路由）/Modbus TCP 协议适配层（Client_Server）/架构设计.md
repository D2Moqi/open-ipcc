模块以 `IotProtocol` 接口为统一入口，提供两个并列的实现：`tcpclient/IotModbusTcpClientProtocol`（主动轮询从站）和 `tcpserver/IotModbusTcpServerProtocol`（被动接收设备连接）。每个协议实现遵循相同的内部分层：
- `codec/`：仅 Server 侧使用 `IotModbusFrame` + `RecordParser` 实现的自定义帧编解码器（`IotModbusFrameDecoder`/`Encoder`），Client 侧复用 Netty 风格的 Vert.x TCP 客户端。
- `handler/upstream` & `handler/downstream`：上行将 Modbus 响应解析为物模型属性并写入消息总线；下行订阅外部指令并通过连接管理器转发到具体设备。
- `manager/`：`ConnectionManager` 维护设备连接池，`ConfigCacheService` 通过 `IotDeviceCommonApi` 拉取配置并缓存，`PollScheduler` 基于 Vert.x 定时器按点位周期发起读/写请求，Server 侧额外有 `PendingRequestManager` 管理超时未响应的请求。
- `common/`：`IotModbusCommonUtils` 集中定义 FC01~FC16 常量、CRC-16/MODBUS 校验、寄存器↔原始值/物模型值的双向转换（支持 INT16/UINT16/INT32/UINT32/FLOAT/DOUBLE 及多种字节序 ABCD/BA/CDAB/DCBA/BADC），被 Client/Server 两侧共享。
依赖方向单向向外：协议实现 → Manager/Handler/Codec → common utils → 上层 `core.biz` API 与 `gateway.service` 消息服务，不反向依赖业务模块。
