- 上行处理器统一继承 `IotCoapAbstractHandler`，通过重写 `requiresAuthentication`、`getProductKey`、`getDeviceName` 和 `handle0` 来定制行为，避免重复的认证与响应逻辑。
- 每个业务处理器采用「Handler + Resource」配对：Resource 仅负责挂载到 CoAP 路径并委托给 Handler，Handler 专注业务处理与返回 `CommonResult`。
- 设备鉴权通过自定义 CoAP Option 2088 携带 Token，并在抽象基类的 `beforeHandle` 中统一校验，需要认证的子类只需覆盖 `requiresAuthentication()` 为 true。
- 异常处理统一捕获 `ServiceException`、`IllegalArgumentException` 及未知异常，并转换为 `CommonResult.error(...)` 响应，保证 CoAP 客户端收到一致的 JSON 错误体。
- 外部依赖（如 `IotDeviceTokenService`、`IotDeviceMessageService`）通过 `SpringUtil.getBean` 懒获取，而非构造函数注入，保持处理器无 Spring 装配依赖。
