模块以 `IotEmqxProtocol` 作为 `IotProtocol` 接口的 EMQX 实现，统一封装生命周期管理：启动时创建 Vert.x 实例、启动 HTTP Hook 服务（路由 `/mqtt/auth`、`/mqtt/acl`、`/mqtt/event`）并连接 EMQX Broker；停止时按相反顺序释放资源。
- 配置层：`IotEmqxConfig` 通过 Jakarta Validation 注解声明 MQTT 连接参数、Will、SSL/TLS、HTTP Hook SSL 等配置项，由上层 `ProtocolProperties` 注入。
- 上行方向（设备→系统）：`IotEmqxUpstreamHandler` 接收 MQTT publish 回调，解析 topic 提取 productKey/deviceName，反序列化为 `IotDeviceMessage` 后通过 `IotDeviceMessageService` 发送到消息总线；`IotEmqxAuthEventHandler` 处理 EMQX 调用的三个 HTTP 接口——认证（支持一型一密注册）、ACL 权限校验（基于 `IotMqttTopicUtils` 判断订阅/发布是否允许）、客户端连接/断开事件（转换为在线/离线状态消息）。
- 下行方向（系统→设备）：`IotEmqxDownstreamSubscriber` 继承 `AbstractIotProtocolDownstreamSubscriber`，从 `IotMessageBus` 消费下行消息后交由 `IotEmqxDownstreamHandler` 根据方法构建主题并调用 `IotEmqxProtocol.publishMessage` 发布到 Broker。
- 重连机制：通过 Vert.x 定时任务周期性检查 MQTT 连接状态，断开时执行同步重连；所有阻塞操作使用 `executeBlocking` 避免阻塞 event-loop。
- 依赖方向：本模块仅依赖 gateway 核心抽象（`IotProtocol`、`AbstractIotProtocolDownstreamSubscriber`、`IotMqttTopicUtils`）和 core 层的设备 API/消息模型，不反向依赖业务模块。
