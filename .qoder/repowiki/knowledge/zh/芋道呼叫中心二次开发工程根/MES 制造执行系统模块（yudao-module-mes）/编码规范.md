- 每个业务域（cal/dv/md/pro/qc/tm/wm）在 api 模块下以同名子包集中定义领域枚举（如 MesProWorkOrderStatusEnum、MesWmTransferTypeEnum），并在 server 模块的 controller/service/dal 中复用。
- 所有业务异常通过 ErrorCodeConstants 中以 1_040_xxx_xxx 分段编号的 ErrorCode 常量声明，按业务域分组注释（如 MES 基础数据、仓库管理、质量管理等）。
- 服务端代码严格遵循 controller/admin/{domain}/... → service/{domain}/*Service + *ServiceImpl → dal/{domain}/{entity}/*Mapper 的分层目录结构，controller 与 DO/Mapper 的包路径一一对应。
- RPC 服务标识集中在 ApiConstants 中维护 NAME、PREFIX、VERSION，避免在各处硬编码服务名与路由前缀。
- 自动编码生成（md/autocode）采用策略模式：strategy 目录下按不同规则实现 MesMdAutoCodePartService，便于扩展新的编码规则。
- 测试用例镜像业务包结构放置在 src/test/java/cn/iocoder/yudao/module/mes/{service|dal}/... 下，并使用 application-unit-test.yaml 与 resources/sql 脚本进行隔离测试。
