模块采用 Maven 多模块结构：`yudao-module-pay-api` 仅包含 Feign 接口、DTO 与枚举常量，作为跨服务 RPC 契约；`yudao-module-pay-server` 为可独立部署的 Spring Boot 应用，内部按领域分层组织：controller（admin/app 双端）、service（各业务域 Service/ServiceImpl）、dal（DO + MyBatis Mapper + Redis DAO）、convert（MapStruct 转换器）、framework（配置、安全、定时任务）以及核心 `framework/pay/core/client` 支付客户端抽象层。

- 支付渠道抽象：通过 `PayClientFactory` / `AbstractPayClient` / `PayClientConfig` 定义统一接口，`PayClientFactoryImpl` 在构造时以 `ConcurrentHashMap` 将 `PayChannelEnum`（wx_*、alipay_*、wallet、mock）映射到具体实现类（`Wx*PayClient`、`Alipay*PayClient`、`WalletPayClient`、`MockPayClient`），运行时通过反射实例化并缓存，新增渠道只需注册映射。
- 业务流程：Controller → Service → DAL/Redis，订单提交时经 `PayOrderServiceImpl.submitOrder` 调用 `channelService.getPayClient` 获取对应渠道客户端执行 `unifiedOrder`，再通过 `PayNotifyService` 处理异步回调；退款、转账、钱包充值遵循相同模式。
- 数据访问：每个实体一对 DO+Mapper（如 `PayOrderDO`/`PayOrderMapper`），扩展信息拆表（`PayOrderExtensionDO`），分布式号段与锁通过 `redis/no`、`redis/wallet`、`redis/notify` 下的 RedisDAO 提供。
- 定时任务：`job/order`、`job/refund`、`job/transfer`、`job/notify` 分别负责订单过期、三方状态同步与通知重试。
- 依赖方向：server 依赖 api 模块（Feign 接口），service 不反向依赖 controller，DAL 只依赖框架通用组件。
