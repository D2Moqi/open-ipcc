模块以 `EslConnectionManager` 为入口，聚合多个 `EslConnection`（每个对应一个 FS 节点），通过 `EslAutoConfiguration` 在 Spring Boot 容器中完成 Bean 装配：将 `EslClientProperties` 转为 `EslClientConfig`，扫描并注册业务方的 `EslEventListener`/`EslConnectionListener`/`EslMonitorListener`，按需创建 `EslEventRouter`、`EslMetrics` 及 Redis 协调器。

内部按职责分层：
- 传输层 (`netty/`)：`EslChannelInitializer` + `EslFrameDecoder` + `EslMessageEncoder` + `EslProtocolHandler` 实现 ESL 协议编解码、auth/request→auth 响应、COMMAND_REPLY/API_RESPONSE 匹配、disconnect-notice 处理；同步命令通过 `CompletableFuture` + `orTimeout` 实现超时控制，响应匹配使用 `ConcurrentLinkedQueue` 队列 FIFO 消费。
- 连接层 (`EslConnection` + `EslConnectionManager`)：封装单连接生命周期（DISCONNECTED→CONNECTING→CONNECTED→AUTHENTICATED→RECONNECTING）与重连策略，管理器负责多节点注册/移除、随机选择、批量 bgapi 发送、对账式 `syncNodes`。
- 事件层 (`router/` + `interceptor/`)：`EslEventRouter` 维护事件名→处理器映射，支持 `SINGLE_THREAD`/`FULL_CONCURRENT`/`CHANNEL_HASH` 三种执行模式，并通过 `EslEventInterceptor` 链实现 before/after 拦截；`BACKGROUND_JOB` 走独立线程池隔离。
- 协调层 (`coordinator/`)：定义 `EslMonitorCoordinator` 接口，默认实现 `RedisEslMonitorCoordinator` 基于 Redis SET NX EX 实现分布式监听权竞争与续期，通过 `ApplicationReadyEvent` 延迟启动避免与 Bean 初始化并发冲突。
- 传输数据模型 (`transport/`)：`EslMessage`/`EslEvent`/`SendMsg`/`CommandResponse` 等纯数据结构，与 Netty/Spring 解耦。

依赖方向：spring → coordinator/netty/router/transport → exception/metrics/annotation；Spring 自动配置通过 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 暴露，所有 Spring/Redis 依赖标记 `optional`，使模块可被非 Spring Boot 工程作为普通 jar 复用。
