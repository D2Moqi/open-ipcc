模块采用 controller → service → dataobject 三层结构：
- Controller 层（controller/admin/autocall）：`AutocallTaskController` 暴露 `/cc/autocall-task` REST 接口，负责任务的 CRUD、分页、Excel 导出、立即执行、暂停/取消、刷新统计；`AutocallTaskRecordController` 提供执行记录分页查询。
- Service 层（service/autocall）：`AutocallTaskService`/`Impl` 封装任务生命周期（创建、更新、删除、状态机切换为待执行/执行中/已完成/已暂停/已取消）、拆分号码生成记录并触发 ESL originate、定时扫描到期任务；`AutocallTaskRecordService`/`Impl` 维护每条被叫的呼叫记录及结果回写；`AutocallTaskScheduler` 通过 `@Scheduled(fixedDelay=30000)` 每30秒扫描待执行且到期的任务；`AutocallTaskResultCallback` 作为 `@Primary` 实现 `AutocallResultCallback`，由 FS 挂断事件回调驱动，将 `AutocallResult` 映射为记录状态并刷新任务统计。
- DataObject 层（dal/dataobject/autocall）：`AutocallTaskDO` 对应 `cc_autocall_task` 表，保存任务配置、状态与统计计数；`AutocallTaskRecordDO` 对应 `cc_autocall_task_record` 表，保存单次外呼的执行明细。
依赖方向单向：Controller → Service → DO，并通过 `AutocallResultCallback` 反向接入 call 模块的 ESL 事件处理链路，形成“任务调度→ESL外呼→回调回写”的闭环。
