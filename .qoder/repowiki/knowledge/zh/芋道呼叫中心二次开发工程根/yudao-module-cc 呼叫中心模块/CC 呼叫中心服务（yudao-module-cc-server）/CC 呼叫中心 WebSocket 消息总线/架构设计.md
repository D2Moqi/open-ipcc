模块以 `CcWebSocketAutoConfiguration` 为统一装配入口，按职责划分为若干子包：
- `config`：通过 `@EnableWebSocket` + `WebSocketConfigurer` 注册 `/cc/ws` 路径、握手拦截器（`LoginUserHandshakeInterceptor`）以及授权定制器；`CcWebSocketProperties` 暴露 `path`、`senderType`、心跳等配置。
- `core/handler`：`CompositeWebSocketHandler` 作为顶层处理器，依据 `SipAnalysisUtil.isSipMessage` 将文本消息路由到 `JsonWebSocketMessageHandler`（JSON 业务消息）或 `SipWebSocketMessageHandler`（SIP 协议），二进制消息一律走 SIP 通道。
- `core/session`：`CcWebSocketSessionManager` 抽象会话管理，`WebSocketSessionManagerImpl` 维护用户类型+编号到 `WebSocketSession` 的映射，`WebSocketSessionHandlerDecorator` 在连接建立/关闭时联动 `SysAgentService` 完成坐席上下线状态同步。
- `core/message`：定义 `JsonWebSocketMessage`、`CcWebSocketMessagePayload`、`CcWebSocketEventEnum`、`AgentStatusData` 等统一消息载体。
- `core/listener`：`CcWebSocketMessageListener<T>` 事件监听接口，由 `JsonWebSocketMessageHandler` 根据消息 `type` 分发到具体监听器。
- `core/sender`：`CcWebSocketMessageSender` 接口 + `AbstractCcWebSocketMessageSender` 基类封装了按 sessionId/userType/userId 查找 Session 并发送 `TextMessage` 的通用逻辑；各后端实现（`local`、`redis`、`rabbitmq`、`rocketmq`、`kafka`）分别位于对应子包，每个实现都配套一个同名 Consumer 用于接收远端广播的消息再转发给本地 Session。`LocalCcWebSocketMessageSender` 直接写内存，其余实现通过各自 MQ 模板发布/订阅消息。
- `core/security`：握手阶段注入登录用户信息，并对请求进行鉴权定制。
依赖方向单向：handler → session → sender；自动配置通过 `@ConditionalOnProperty(prefix = "cc.websocket", name = "sender-type")` 条件装配不同 sender 实现，运行时仅激活一种。
