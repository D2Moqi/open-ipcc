模块以 `esl/` 为核心，围绕 `ipcc-fs-esl` SDK 构建三层结构：
- 连接与命令层：`client/FsClient` 作为业务级 ESL 命令门面，委托底层 `EslConnectionManager`/`EslMonitorCoordinator` 完成 sendmsg/bgapi/sync 命令发送、FS 节点选择、连接池同步（reloadConnections/disconnectByConfigId）以及重连后的僵尸通道对账（reconcileChannels）。
- 事件处理层：`handler/event/*` 下每个类对应一个 FS 事件（如 CHANNEL_ANSWER、CHANNEL_HANGUP_COMPLETE），继承 `factory/AbstractFsEslEventHandler` 并通过 SDK 的 `@EslEventName` 注解自动注册到 EslEventRouter；事件处理器从 Redis 中取 CallInfo，再经 `FsEslProcessFactory` 按 `ProcessEnum` 路由到 `handler/call/FsAbstractCallProcess` 的具体流程实现（如桥接、IVR）。
- 路由与 XML_CURL 层：`handler/route` 提供 IVR 等拨号计划回调，`handler/xmlcurl` 通过 `factory/FsXmlCurlEventStrategyFactory` + `@XmlCurlEventName` 策略工厂分发 ACL/Dialplan 等 xml_curl 请求。
- 辅助子包：`bridge`（连接桥接）、`queue`（呼叫队列）、`service`（CallInfo 缓存）、`annotation/enums/constant/dto/vo/utils` 提供常量、枚举、DTO 与工具；`interceptor/TraceEslEventInterceptor` 做事件追踪。
- `tts/` 独立于 ESL 事件流，定义 `FileTtsService` 接口及 `AbstractFileTtsHandler` 抽象处理器，当前实现为阿里云文件 TTS（`AlFileTtsHandler`），通过 `Consumer<File>` 回调输出音频文件。
依赖方向单向：event handler → call process → FsClient → ipcc-fs-esl SDK；tts 与 esl 之间无直接耦合。
