- 节点处理器统一继承 `AbstractIFlowNodeHandler` 并实现 `execute(FlowDataContext)`，由父类统一处理异常、持久化和结束通知，避免各节点重复生命周期代码。
- 新增节点类型通过在 `FlowNodeTypeEnum` 中声明 type→handler 映射，并在 `constant/FlowNodeHanderConstant` 中定义 Bean 名，由监听器动态解析装配，禁止硬编码 switch。
- 节点行为配置采用独立 Properties DTO（`FlowXxxNodeProperties`）+ JSON 序列化存储于 `flowData.properties` 字段，运行时通过 `JSONObject.parseObject` 反序列化为具体类型。
- 条件判断统一通过 `FlowConditionEvaluator.evaluate(branch, variables)` 完成，变量 key 约定为「组件ID.输出值key」，operator 集中维护在 evaluateCondition 的 switch 中。
- Service 层对流程相关数据的跨租户访问方法统一标注 `@TenantIgnore`，并提供 `NoTenant` 后缀方法（如 `getFlowInfoNoTenant`）供引擎内部调用。
- 流程状态变更通过 `FlowNoticeService.notice` 发送事件（如 TRANSFER、END），节点异常时设置 `hangUpCause` 并触发结束通知，保证外部系统可感知流程终态。
