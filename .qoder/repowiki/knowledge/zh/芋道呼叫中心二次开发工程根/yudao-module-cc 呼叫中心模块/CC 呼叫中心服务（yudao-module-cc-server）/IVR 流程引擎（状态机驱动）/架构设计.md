模块以 Spring StateMachine 为核心运行时：`config/RedisStateMachineConfig` 通过 `@EnableStateMachine` 启用状态机，并自定义 `RedisStateMachinePersister` 使用 Jackson 序列化将状态上下文持久化到 Redis；`listener/FlowStateMachineListener` 监听 `stateEntered/stateExited`，在状态进入时从 Redis 读取当前节点配置，通过 `FlowNodeTypeEnum.getHandler()` 解析出 Bean 名并用 `SpringUtils.getBean` 动态获取对应的 `AbstractIFlowNodeHandler` 子类执行；每个节点处理器继承 `AbstractIFlowNodeHandler`，统一封装 `handle` 生命周期（异常时挂起、调用 `FlowNoticeService` 通知、执行后调用 `persister.persist` 持久化状态）。节点类型与处理器通过 `FlowNodeTypeEnum` + `FlowNodeHanderConstant` 解耦，新增节点只需实现一个 Handler 并在枚举中注册。条件分支由 `FlowConditionEvaluator` 根据 `FlowConditionBranch`/`FlowConditionItem` 的 matchType（ANY/ALL）和 operator（IS_EMPTY、CONTAINS、EQ、GT、LENGTH_EQ、IS_TRUE 等）求值。路由策略集中在 `handler/route/` 下（坐席组、指定坐席、外呼、SIP），供 Transfer/CallOut 等节点复用。数据层按 service/dal/dataobject 分层：`service/flow/` 暴露 `FlowInfoService`、`FlowInstancesService`、`FlowNodeExecutionHistoryService`，对应 DO 为 `FlowInfoDO`、`FlowInstancesDO`、`FlowNodeExecutionHistoryDO`，其中实例与历史查询标注 `@TenantIgnore` 以支持跨租户访问。属性类集中在 `properties/`，每个节点类型对应独立的 Properties DTO（如 `FlowPlaybackNodeProperties`），由监听器反序列化为具体类型。
