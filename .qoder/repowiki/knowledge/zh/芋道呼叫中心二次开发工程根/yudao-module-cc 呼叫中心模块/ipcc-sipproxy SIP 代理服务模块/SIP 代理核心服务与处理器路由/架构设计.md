模块以 `SipProxyService`（实现 `javax.sip.SipListener`）为唯一协议栈入口，在 `@PostConstruct` 中创建 `SipStack`、UDP/TCP 两个 `SipProvider`，并注入 `MessageFactory/HeaderFactory/AddressFactory` 到各组件。入站分两条路径：
- WebSocket 路径：`handleWebSocketSipMessage` 解析文本后通过 `WsSipRequestHandlerFactory` 按方法分发到 `WsXxxRequestHandler`；响应经 `SipResponseHandlerFactory` 路由。
- 原生 SIP 路径：`processRequest/processResponse` 先执行来源识别（`MessageSourceIdentifier`）、速率限制（`SipRateLimiter`）、第三方 IP 白名单（`IpWhitelist`），再交由 `SipRequestHandlerFactory` 分发到 `SipXxxRequestHandler`。
处理器采用工厂+注解注册模式：自定义 `@SipMethod` 标注方法名，`*RequestHandlerFactory` 在 `init()` 时扫描 Spring Bean 自动注册，未匹配则回退到 Default Handler。横向能力由独立子包提供：`auth/GatewayAuthManager` 处理 RFC2617 Digest 407 挑战与 qop=auth；`session/SipSessionManager` 用 Redis 持久化 `SessionInfo` 及 ws↔用户映射；`forwarder/SipMessageForwarder` 负责向 FreeSWITCH/第三方发送；`node/SipNodeManager` 管理 FS 节点；`utils/SipAnalysisUtil` 封装 JAIN-SIP 解析。依赖方向单向：service → handler factory → handler → forwarder/session/auth，support 包仅暴露常量与数据模型供外部 provider 实现。
