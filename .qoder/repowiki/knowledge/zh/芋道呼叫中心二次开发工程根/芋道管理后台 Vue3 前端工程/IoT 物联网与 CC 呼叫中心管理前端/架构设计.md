模块按业务域划分为两个并列子域：`src/views/iot/` 与 `src/api/iot/` 对应 IoT 物联网，`src/views/cc/` 对应呼叫中心，二者共享同一套 UI 基础设施（ContentWrap、Pagination、Icon、useMessage、v-hasPermi 指令等）。每个业务目录遵循「视图层 views + 接口层 api」一一对应的分层：views 下按资源维度再细分子目录（如 device/device、product/product、rule/scene、ota/firmware），每个资源通常包含 index.vue（列表+查询）、Form.vue（新增/编辑弹窗或抽屉）、detail/（详情页）；api 下同名目录导出以 `XxxApi` 命名的对象，集中封装 GET/POST/PUT/DELETE 请求，并通过 TypeScript interface 定义 VO/ReqVO。

复杂交互通过子组件拆分：IoT 物模型使用 ThingModelProperty / ThingModelEvent / ThingModelService / ThingModelTSL 及 dataSpecs 下的类型化数据定义组件；IoT 场景联动规则采用 RuleSceneForm 作为主表单，内部拆分为 BasicInfoSection / TriggerSection / ActionSection 三个 section，并进一步通过 configs/inputs/selectors 等子组件实现条件与动作的动态配置；IoT 数据流转规则在 sink 侧为每种下游（Database/Http/Kafka/MQTT/RabbitMQ/RedisStream/RocketMQ/Tcp/WebSocket）提供独立的 ConfigForm，统一由 DataSinkForm 聚合。

CC 域的 IVR 流程编辑器是独立的重型子模块：`ivrEdit.vue` 基于 LogicFlow 构建流程图画布，节点元数据集中在 `store/ivr.ts` 的 NodeMetadata 与 allNodeDefinitions 中维护，各节点（start/end/playback/receive/condition/method/transfer）以独立 Vue 组件 + 自定义 model（customLeft/customRightOne/customBilRightOne/customCondition 等）注册到 LogicFlow，并通过 TeleportContainer 渲染；状态管理使用 Pinia store（`store/ivr.ts`），常量与枚举集中在 `consts/`，节点尺寸同步与表单事件冲突通过 `node/utils/formEventGuard.ts` 与防抖逻辑解决。

依赖方向：views → api → `@/config/axios`；跨领域不互相引用，仅共享全局工具（dict、utils、store）。权限控制通过 `v-hasPermi` 指令绑定如 `iot:device:create`、`cc:area-code:delete` 等后端权限码。
