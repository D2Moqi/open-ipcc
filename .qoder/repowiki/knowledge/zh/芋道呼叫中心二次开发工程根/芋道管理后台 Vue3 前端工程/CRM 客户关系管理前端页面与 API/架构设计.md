模块按业务域在 `src/views/crm/` 下划分子目录（clue、customer、business、contract、receivable、product、contact、followup、permission、backlog、statistics），每个业务域遵循统一的「列表页 + 表单弹窗 + 详情页」结构：列表页（如 `customer/index.vue`）通过 `ContentWrap` + `el-form` 搜索栏 + `el-table` + `Pagination` 组合，调用对应 `@/api/crm/<domain>/index.ts` 中的分页接口；新增/编辑通过同目录 `<Domain>Form.vue` 以 Modal 形式复用；详情集中在 `<domain>/detail/index.vue`，由 `<Domain>DetailsHeader.vue` 和 `<Domain>DetailsInfo.vue` 拆分展示，并通过 `BizTypeEnum.CRM_<DOMAIN>` 与通用的 `FollowUpList`、`ContactList`、`ContractList`、`PermissionList`、`OperateLogV2` 等跨域组件集成。

`backlog` 作为统一待办入口，左侧菜单聚合各域待处理数量（今日联系、分配线索、待审核合同/回款、即将到期合同、公海提醒等），右侧按需渲染对应 `components/*List.vue` 子组件。

`statistics` 为纯数据看板，按 customer/funnel/performance/portrait/product/rank 等维度组织，每个 tab 是独立的图表组件，通过父级 `queryParams` 驱动刷新。

API 层 `src/api/crm/` 与视图一一对应，每个文件使用 `request.get/post/put/delete/download/upload` 封装后端 `/crm/*` 路由，并导出 TypeScript VO 类型；统计数据类 API（如 `statistics/rank.ts`）采用对象命名空间 `StatisticsRankApi` 集中导出。权限控制通过全局指令 `v-hasPermi=['crm:*:action']` 在按钮级裁剪操作。
