- 每个组件采用 `index.ts` 作为对外出口，实际实现放在同级的 `src/` 目录下，便于按需引入与 tree-shaking。
- 布局渲染采用策略模式：`Layout.vue` 根据 `appStore.getLayout` 选择 `useRenderLayout` 中对应的 render* 函数，新增布局只需追加一个 render 方法。
- Pinia store 统一使用 `defineStore('xxx', { state, getters, actions })` 形式组织，并通过 `wsCache` 在 action 中持久化 theme、layout、isDark 等用户偏好。
- 组件样式类名通过 `useDesign().getPrefixCls()` 生成带命名空间的前缀，避免全局 CSS 污染。
- 复杂组件内部按职责拆分子目录（如 DiyEditor 的 mobile/*、bpmnProcessDesigner 的 package/{designer,penal,palette}），并在根目录保留 `index.ts` 聚合导出。
- 表单/表格等高级组件通过 `componentMap`、`helper.ts`、`types.ts` 集中维护字段映射、校验规则与类型定义，业务侧以声明式 schema 驱动渲染。
