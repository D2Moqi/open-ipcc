模块由两个并列的业务域组成，均遵循 `views/<domain>/` + `api/<domain>/` 的双目录结构：
- IM 域 (`src/views/im/`)：以 `home/index.vue` 为全屏沉浸式壳，左侧 `components/ToolBar.vue` 切换消息/好友/群聊三个 Tab，右侧通过 `<router-view>` + `keep-alive` 缓存子页面；状态集中在 `store/` 下的多个 Pinia store（conversationStore、messageStore、friendStore、groupStore、channelStore、websocketStore、rtcStore 等），业务逻辑下沉到 `composables/`（useMessagePuller、useMessageSender、useVoicePlayer、useLiveKitRoom 等），UI 组件按 `components/{friend,group,user,rtc,picker,card}` 细分；实时通信通过 `websocketStore` 建立 WebSocket 长连接，离线数据经 `utils/db.ts` 写入 IndexedDB，并由 `useMessagePuller` 在启动时并发拉取增量。
- WMS 域 (`src/views/wms/`)：采用标准后台 CRUD 布局，`home/index.vue` 作为仪表盘聚合各统计图表组件，`inventory/`、`md/`（item/category/brand/warehouse/merchant）、`order/`（check/movement/receipt/shipment）各自独立路由，每个列表页配套 `Form.vue`、`Detail.vue`、`Print.vue` 以及可选的 `components/*Select.vue` 选择器。
- API 层 (`src/api/im/`)：按后端资源维度划分目录（conversation、friend、group、message、rtc、manager/*），每个 `index.ts` 仅暴露接口函数与 VO 类型，统一通过 `@/config/axios` 发起请求，被 views 中的表单/列表直接调用。
- 依赖方向：views → composables/store → utils → api → axios；IM 的 store/composables 之间通过 Pinia 共享状态，不直接跨文件调用 DOM。
